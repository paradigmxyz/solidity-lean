# AGENTS.md

Routing map for agents working in this repository. What the repository claims is in
[README.md](README.md) and [ARCHITECTURE.md](ARCHITECTURE.md); the theorem we publish and the
trust rule per edge are in [docs/CERTIFICATION_TARGET.md](docs/CERTIFICATION_TARGET.md). Read
the scoped `AGENTS.md` of a directory before editing under it.

## Goal and source of truth

- The goal is generic certification of any supported contract: one generic driver and one fixed
  theorem statement (`Certified`, docs/CERTIFICATION_TARGET.md) for every contract, not
  per-contract proofs. A contract or feature outside `docs/SUPPORTED_ENVELOPE.md` is reported
  BLOCKED with the reason; never special-case it into a pass.
- Source truth is the independent solc-AST semantics: pinned solc AST -> SolidCore
  (`SolidCore/Solidity/`). The generic fragment's foundation is `Generic.Stage`
  ([Stage.lean](SolidCore/Refinement/Generic/Stage.lean): `check`, `stageAt`, source vs
  solar's lowered MIR); widen its fragment (`eraseFn`, `symTree`) rather than adding
  contract-specific stages.
- solar's HIR is never source truth: at most optional, untrusted matching hints or certificates
  that a kernel check validates against the solc-AST side. No result may depend on HIR being right.

## Setup and narrow checks

- Toolchain: `lean-toolchain` pins `leanprover/lean4:v4.35.0`, Mathlib is `v4.35.0`
  (`lakefile.lean`, `lake-manifest.json`). Never change either to make something build.
- `lake exe cache get` fetches Mathlib's prebuilt oleans; run it before the first build.
- After editing `lakefile.lean` or the manifest, reconfigure: `lake -R build <target>`.
- Build the narrowest target that covers the change: `lake build -KleanMemory=<MB> <Module.Name>`
  for a module or a `lean_lib` name, `lake env lean -M <MB> path/File.lean` for one file.
  `lake build` with no target is the full default library; leave it to CI.
- Set `LEAN_NUM_THREADS` explicitly (CI uses 2; `Verify/Discharge/discharge.sh` defaults to 1).
- The reference build order, targets and per-step memory caps are the steps of
  [.github/workflows/refinement.yml](.github/workflows/refinement.yml).
- Existing gates: `scripts/fast_inner_gate.sh` (semantic spine + laws),
  `scripts/refinement/check.sh`, `scripts/refinement/axiom-audit.sh` (axiom closure),
  `scripts/verify/check.sh`, `Verify/Discharge/discharge.sh`. Each script's header says what
  it checks and what to build first.

## Library-first proof workflow

1. Search before building machinery: Lean core and Std, Mathlib, Loom (`Loom/`, vendored),
   EthLib, and the lemmas already here (`rg`, `exact?`, `apply?`, `#find`, Loogle).
2. Keep four concerns in separate modules and separate commits: **semantics** (what a run
   means), **VC generation** (what must hold), **invariant discovery** (untrusted search for
   loop invariants, specs, certificates) and **discharge** (kernel-checked proof of each VC).
   A discovery tool's answer is input to a proof, never evidence.
3. Prove against the exact published statement; do not weaken a statement to make it close.

## Trust and acceptance

A result counts only if all of these hold for its whole dependency closure:

- It proves the exact theorem statement the target names (every premise printed in it).
- Transitive axioms are only `propext`, `Classical.choice`, `Quot.sound`, checked with
  `#print axioms` / `Lean.collectAxioms` (`scripts/refinement/axiom-audit.sh`).
- No `sorry`/`admit` (`sorryAx`) anywhere in it.
- No `native_decide`, `Lean.ofReduceBool`, `Lean.trustCompiler` or any other
  native-evaluation certificate path. Existing native uses (such as the `SolidCoreNative`
  library) are not acceptance evidence.

`sorry` is allowed only in isolated scratch files (`tmp/`, gitignored, or `/tmp`) that no
`lean_lib` root imports; never commit one into a module an accepted target can reach.

## Performance and parallel work

- Measure tactic (elaboration) time, kernel checking time and proof term size separately
  (`set_option profiler true`, `set_option trace.profiler true`), against a baseline that
  proves the same statement; record results in [docs/PERFORMANCE_LOG.md](docs/PERFORMANCE_LOG.md)
  or the owning results file.
- Parallel lanes have disjoint writers: one owner per file and per generated directory; build
  in a separate checkout (separate `.lake`) rather than sharing one.
- Admit a build only when its measured peak RSS (`/usr/bin/time -v`, or a previous run's
  record) fits the memory left; cap each Lean process with `-KleanMemory` / `-M`.

## Skills

Pinned copies of [leanprover/skills](https://github.com/leanprover/skills) are in
`.agents/skills/` ([PROVENANCE.md](.agents/skills/PROVENANCE.md)). Read the named file when
the trigger applies; the overrides here win over the skill.

| Trigger | Load | Local override |
|---|---|---|
| Writing or repairing a proof | [lean-proof](.agents/skills/lean-proof/SKILL.md) | Its `by sorry` placeholders are scratch-only (see above). "No sorry and no errors" is not done: the axiom gate above is. |
| A Lean, Mathlib or EthLib behaviour looks like an upstream bug | [lean-mwe](.agents/skills/lean-mwe/SKILL.md) | Minimize outside this repository; filing upstream is a maintainer's call. |
| Fetching caches or building | [mathlib-build](.agents/skills/mathlib-build/SKILL.md) | Use its `cache get` and quiet-build advice on this repository's narrow targets; its Mathlib-repository commands (`lake build Mathlib ...`, `runLinter`) do not apply. |
| On demand only: a behaviour change reproduced across Lean toolchain versions | [lean-bisect](.agents/skills/lean-bisect/SKILL.md) | Bisect a self-contained file outside this repository; a result never changes `lean-toolchain` here. |

Not adopted: upstream `lean-setup` (CMake build of the Lean compiler, not Lake) and the
`lean-pr`/`mathlib-pr` conventions (upstream-specific).
