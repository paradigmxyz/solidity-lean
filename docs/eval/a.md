# Lane A: frozen baseline, receipt schema, scaling fixtures, kernel replay

Toolchain leanprover/lean4:v4.35.0, base 6dd035dc (+ the eval lanes' uncommitted files), hosted Hand
(5 CPU, 14 GiB), every check through `scripts/eval/check.sh A` (LEAN_NUM_THREADS=1, `-M 5000`,
at most 2 Lean checks on the box, Lane A used one slot at a time). Measured 2026-11-15.

## What is here

| File | What |
| --- | --- |
| `Verify/Eval/A/schema.json` | The row every lane reports (JSON Schema). |
| `scripts/eval/fixtures/summarize.py` | Receipts (`~/eval-receipts.jsonl` + logs + replay output) and lane rows → schema rows (`--jsonl`) and a markdown table with doubling ratios metric(2n)/metric(n). |
| `scripts/eval/fixtures/gen_solm.py` | Emits `Verify/Eval/A/Fixtures/<Family><n>.lean`, n ∈ {16,32,64,128,256}. |
| `scripts/eval/fixtures/run_baseline.sh` | Runs the fixtures breadth-first through check.sh, writes each .olean, runs the replay, stops a family at its first timeout (600 s of Lean, not counting slot waits), OOM or error. |
| `scripts/eval/fixtures/run_generated.sh` | The same baseline on generated end-to-end modules (no `-o`: lake's build untouched). |
| `Verify/Eval/A/Replay.lean` | Kernel-only replay of every theorem of built modules + rejection checks. |
| `Verify/Eval/A/baseline.jsonl`, `baseline_generated.jsonl` | The frozen rows below, in schema form. |

Use: `python3 scripts/eval/fixtures/summarize.py --lane D --rows my_rows.jsonl` (or just your check.sh
receipts; theorems named `*.baseline` are the baseline, anything else is `new`). For kernel time from
an .olean: `lake env lean --run Verify/Eval/A/Replay.lean <Module>` (write your lane's .olean with
`scripts/eval/check.sh <lane> <file> -o .lake/build/lib/lean/<path>.olean`).

## Schema (one JSON object per measurement)

lane, fixture, family, n, variant (`baseline` | `new[:engine]`), statement (theorem name),
statement_hash (Replay: `Expr.hash` of the type mixed with the body of the `stmt` it names — two
lanes proving `X.stmt` get the same hash), status (`ok` | `timeout` | `oom` | `error[:reason]`),
wall_s, elab_ms (front-end profiler categories), tactic_ms (simp + dsimp + tactic execution +
omega/grind/decide…), interp_ms, kernel_ms (profiler "type checking", whole file),
kernel_recheck_ms (`#kernel_recheck`, main declaration), kernel_replay_ms (Replay.lean: theorem +
its `_proof_` aux decls, from the .olean), dag_nodes (`#proof_stats` dag + aux_dag), tree_nodes
(capped at 1e7 by Measure), aux_decls, olean_bytes, peak_rss_kb, heartbeats (null unless the lane
measured them), axioms_ok / axioms (Replay: ⊆ propext, Classical.choice, Quot.sound), generated
(true = generated end-to-end artefact), toolchain, machine, commit, log, limit_s.

## Fixtures (HANDWRITTEN, generated by gen_solm.py)

Each file: `def model` on `SolM`, `def stmt : Prop` (a Loom `wp` goal in `bump_spec` style, or a
`triple` for the loop body), `theorem baseline : stmt` by today's engine: `simp only [model, wp_bind,
wp_pure, wp_sload, wp_sstore, wp_revert, wp_ite, ite_apply, dite_apply]` (the `sc_vcgen` set) then
`sc_close`; `#proof_stats` and `#kernel_recheck` at the end. Imports: Verify.Basic, Verify.Tactic,
Verify.Eval.Common.Measure. n counts monadic primitives.

* **Straight** — n/2 load/store pairs, slot i+1 := slot i + 1; post `s' m = s 0 + m` from `s 0 < 2^128`.
* **Shared** — one expression `(x+1)*(x+2)+x*3` stored into n-1 slots; the post repeats it n-1 times.
* **Branch** — n/3 sequential `require(slot i < 2^255)` guards, each with a store of the doubled
  value; n/3+1 paths; any revert allowed.
* **Memory** — n/2-1 distinct slots written, then read back and returned as a list.
* **LoopBody** — body of `while i < N` with n/2 counters (load+store each), proved against a
  supplied invariant and variant in the `triple` form `triple_whileM` needs (as
  `CounterBump.body_step`). Its proof adds `obtain` of the invariant, `hv : N-(i+1) < N-i` and the
  Assn lattice lemmas (`Pi.inf_apply, inf_Prop_eq, Pi.top_apply, …`) before `sc_close`.

## Kernel replay harness (Verify/Eval/A/Replay.lean)

`lake env lean --run Verify/Eval/A/Replay.lean M1 M2 …` imports the modules (no elaboration),
re-adds each theorem of each module under `<name>._replay` with its saved type and value via
`Environment.toKernelEnv.addDeclCore` (the call of `#kernel_recheck`), times each and the total,
reports axioms and statement hash, then shows the same path REJECTS (1) a theorem of the module
whose value is swapped for `Nat.lt_irrefl`'s proof and (2) `True` proved by `(0 : Nat)`; exit 1 if any
saved theorem is rejected, any axiom is non-standard, or any ill-typed term is accepted.
Demonstrated on Verify.Basic (28 theorems, 11 ms), Verify.CounterBump (11 theorems, 62 ms;
`bump_spec` 6 ms), every successful fixture and the generated modules above; both rejections fired
every time. Logs: `~/eval-logs/replay-A-*.jsonl`.

## Findings

1. Today's SolM engine scales badly before n = 64 on every family: wall ×4–×10 per doubling where it
   still finishes, kernel ×4–×16, proof DAG ×7.6–×10.8; three families die at 32 or 64 ops (timeout or
   5 GB), two hit simp's step limit. The cost is in `simp` (tactic_ms ≈ elab_ms) and the
   `split_ifs` cascade of `sc_close` over storage reads: `simp only` with this lemma set does not
   reduce literal slot comparisons (`1 % 2^256 = 1000 % 2^256`), so every read leaves a chain of
   ifs that `split_ifs` splits and `omega` refutes.
2. Memory is non-monotone (16: 66 s, 32: 10 s, 64: 31 s): the `sc_arith` cascade (`first | … |
   omega | … | simp_all`) takes a different alternative at different sizes, so the baseline is
   sensitive to which alternative fires; compare per size, not only by ratio.
3. Kernel time is small next to elaboration at these sizes (≤ 3 s), but grows faster (×15–×20 per
   doubling for Shared and Memory) and tracks DAG size; .olean bytes grow ×7–×10 per doubling.
4. Wall includes the `#proof_stats` tree walk (interpreted, capped at 1e7 nodes): up to ~25 s of
   `interpretation`; use tactic_ms / kernel_* for engine comparisons.
5. On the generated Bump/BumpTotal modules the baseline is cheap: ~8 s wall, 1.8 GB, kernel 1–1.6 s,
   replay ≈1 s per module.

## Caveats

* `recheck ms` (in-file `#kernel_recheck`) may include pending async kernel checks: `Measure` takes `env.toKernelEnv` inside the timed region and in Lean 4.35 that waits for earlier theorems' kernel work (Lane G's finding). Use `replay ms` (Replay.lean takes the kernel env before timing) as the kernel-only number. New measurements should set `Elab.async false` and use the lead's `#timed`.

* Profiler categories nest, so elab_ms can exceed wall_s; heartbeats were not measured (null).
* The VerifyEval lib glob includes `Verify/Eval/A/Fixtures`: a `lake build VerifyEval` would try the
  failing sizes (Straight≥32, Shared≥64, Branch≥64, Memory≥128, LoopBody≥32). Build fixtures
  individually.
