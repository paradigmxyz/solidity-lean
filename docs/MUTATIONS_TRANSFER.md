# Mutation acceptance: UniswapV2ERC20.transfer

Can the final transfer theorem
(`Contracts/UniswapV2/ERC20/Certified/Transfer.lean`, `certified`) still check after a plausible
mistake in the bytes, the postcondition, the gas bound or the statement? It must not. Each mutation
below makes one edit, and the table names the first check that refuses it.

```
SOLAR_DIR=<solar checkout> SOLAR_VERIFY=<its solar-verify> scripts/verify/mutant/transfer/run.sh
```

[run.sh](../scripts/verify/mutant/transfer/run.sh) runs the generators
(`uniswap_v2_gen.sh`, `uniswap_v2_stages.sh`, `lake build Contracts.UniswapV2.ERC20.Core`,
`uniswap_v2_transfer_slice.sh`; `--skip-gen` keeps their output), one
`lake build ContractsUniswapV2ERC20Certified`, then
[mutate.py](../scripts/verify/mutant/transfer/mutate.py). It exits 0 only when every mutation is
rejected and both controls pass.

## Method

The tree is never edited. For each mutation, mutate.py writes the edited file under a scratch root
at the same relative path. It then recompiles every module in Transfer's import closure that
imports the edited file, in import order, into an overlay of object files searched before
`.lake/build`. Each module gets its library's options from `lakefile.lean`, plus `-M 6000` and
`LEAN_NUM_THREADS=1`. The overlay mirrors `.lake/build` with symbolic links and replaces only
the recompiled modules, never writing through a link. The first module that fails to check is the
rejecting check, reported as module, declaration, line and first error.

Two controls:

* the same 11 modules compiled the same way from the unedited sources must all pass. A rejection
  therefore comes from the edit, not from the overlay or its options.
* the certificate `tools/certify/gen_ctxgas.py` regenerates from the real bytes must equal
  `Certified/uv2_erc20/CtxGas.lean`.

Bytes mutations edit the runtime bytes (`gen/UniswapV2ERC20/Bytecode.lean` and its manifest) and
are checked twice:

* against the certificate generated for the real bytes, so only the bytes change;
* with the certificate regenerated by `gen_ctxgas.py` for the mutated bytes, as if the untrusted
  inference were rerun on them.

A bytes mutation counts as rejected only when both fail.

The first mutate.py run failed every module with "object file ... does not exist", the controls
included. Lean resolves an import's root directory from the first search path that has it, so an
overlay holding only recompiled modules hid the rest. The fix was to mirror the tree with links;
the control caught the mistake. The run in the table is mutate.py alone, on the build that
run.sh left.

## Limits

* A rejection means the edited proof no longer checks. It is not a proof that the mutant is false.
  The statement mutants are false by construction:
  * self-transfer-alias claims a debit and a credit when caller = to, and `self_max_bytes` shows
    a self-transfer at balance 2^256 - 1 succeeds with the storage unchanged;
  * balance-boundary claims success at s[to] + v = 2^256, where the source reverts on overflow;
  * wrong-expected-type claims every call succeeds.
* step-budget-exhaustion is refused by `sym_exec`'s "different results on this path, or the
  procedure cannot tell". That is incompleteness of the guard's procedure as much as a refutation:
  the bound N = 7 is what the guard proves, not a proved minimum.
* gas-exhaustion lowers the claimed bound by one, and `G_eq` (kernel evaluation of `gasBoundL`)
  refuses it. This checks that the stated bound is the computed one, not that 8199111 gas runs out
  on some call: `Resources` is an upper bound.
* The bytes mutations are refused at `walk_ok`, the decoding of the exact bytes against the final
  EVM IR's layout. A mutation that kept the layout and changed only a compared operand would be
  refused later, by `check_ok`. None of the seven exercises `check_ok` alone.
