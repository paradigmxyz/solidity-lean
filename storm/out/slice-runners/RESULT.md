## Answer for slice-final

**The call-free route does not apply to UniswapV2ERC20: its exact runtime fails the check.** No theorem can discharge
`StaticRunner`/`CalleesRun` for these bytes through `callFree`, and none is labelled as doing so.

- Theorem to cite (a kernel refusal, not a discharge): `SolidCore.Spec.UniswapV2.ERC20.NoCall.runtime_not_callFree :
  SolidCore.Refinement.Solar.AssembleNoCall.callFree code = false`, where `code = Runtime.code` is solar 38b5232's
  `-Ogas --evm-version osaka` runtime (1183 bytes, hex sha256 0bba75d5…e12c).
- Where: `refusedAt_eq : refusedAt code = [903, 1158, 1161, 1162]`, the STATICCALL at 903 (permit → ECRECOVER) and
  RETURNDATASIZE, RETURNDATACOPY, RETURNDATASIZE. `runtime_only_staticcall`: no CALL, CALLCODE, DELEGATECALL, CREATE, CREATE2.
- Consequence for E5: do **not** state the slice with `hP : ∀ gas, StaticRunner gas` (false: `AssembleNoCall.not_forall_staticRunner`,
  so such a theorem is vacuous), and `holds_of_checkCB_callFree` / `assembly_of_checkXB_norm_callFree` cannot be applied.
  The route that needs neither premise for these bytes is slice-final's own guard route (pre-reset WIP on xfer/solar-bundles,
  `storm/out/slice-final/wip`): `AssembleCtxGas.within_of_checkXL` / `forward_of_checkXL`, with permit's blocks in the unchecked
  set F and a guard stage proving transfer-selector runs of the final EVM IR never enter F. I read its statement (no runner
  hypothesis; the frame never reaches F, so the message runner is never consulted). It is **not** merged on 9fb89ee and I did
  not build it; it is slice-final's to land.

## Proved (kernel; `decide +kernel` on the generated bytes; no sorry/native_decide)

Namespace `SolidCore.Spec.UniswapV2.ERC20.NoCall`. Axioms printed by `#print axioms` (also checked in-file by `#guard_msgs`):

| theorem (module) | statement | axioms |
|---|---|---|
| `runtime_not_callFree` (NoCall) | `callFree code = false` | propext |
| `runtime_not_noFaByte` (NoCallFa) | `noFaByte code = false` | propext, Classical.choice, Quot.sound |
| `runtime_has_staticcall` (NoCallDecode) | `(decoded code).any (·.2 == .op 0xfa) = true` | propext |
| `runtime_only_staticcall` (NoCallOnly) | no decoded instruction is CREATE/CALL/CALLCODE/DELEGATECALL/CREATE2 | propext |
| `refusedAt_eq` (NoCallAt) | `refusedAt code = [903, 1158, 1161, 1162]` | propext |
| `scrubWith_size`, `scrubWith_get` (NoCallControl) | scrubbing keeps the size and every byte off the scrubbed counters (by proof, any bytes) | propext (+ Quot.sound for get) |
| `scrubbed_eq`, `scrubbed_callFree` (NoCallControl) | positive control: `scrubWith (refusedAt code) code` (those 4 instructions → INVALID) **passes** `callFree` | propext |
| `staticcall_kept_not_callFree` (NoCallNeg) | negative control: scrubbing 1158/1161/1162 but keeping the STATICCALL is **refused** | propext |

The controls show the refusal is caused by exactly those four instructions (the decode stays aligned; nothing else fails),
and that the STATICCALL alone suffices to refuse.

## Exact bytes (E6 note)

`scripts/verify/uniswap_v2_runtime.sh` (new, committed) writes `Contracts/UniswapV2/ERC20/Runtime.lean` (gitignored, GPL-derived)
from `$SOLAR -Ogas --evm-version osaka --emit bin-runtime` on the port, with solar's commit, the source sha256 and the hex sha256
in its header. It fails closed (exit 1) on unset SOLAR, a failing SOLAR and a missing port (all three run). Run here with solar
38b5232 (`alpharush/certified` head) on port.py's output: 1183 bytes, hex sha256
0bba75d501e65bc87829d7dfbee57711df84c91d2cf44d19907b1a26b043e12c, identical to round 1's bytes. `refusedAt_eq` pins counters of
these bytes: another compiler's bytes fail it by evaluation. The driver's byte binding (E6) is not part of this lane.
