# The meaning of solar-verify's specs

This directory gives the annotations `solar-verify` checks a meaning in Lean, over the calls and
observables SolidCore and EthLib share (`SolarTV.Sem`), so a spec `solar-verify` accepts becomes a
Lean proposition about the contract and, through the certified translation, about solar's bytecode.

## Files

- `Syntax.lean`: the spec language after `solar-verify`'s front end. Terms are integers (math-int
  semantics: no wrapping until a value is stored), with arguments, named returns, storage loads at
  a slot, byte offset and width with their type, `old(..)`, ghosts, `msg.sender`, `msg.value`,
  `block.timestamp` (`__time`), `==>` and `<==>`, bounded `forall` and `exists`, and calls of spec
  functions, opaque (`@custom:opaque`) or inlined by unfolding. A `Manifest` binds a spec to its
  source's sha256, the compiler and the runtime bytecode's sha256.
- `Semantics.lean`: `eval`, total on fuel; mapping and array slots by keccak.
- `Contract.lean`: `Pre` and `Post` of a function spec at a call (selector, ABI decoding,
  requires, and the contract and struct invariants) and `Holds S p scope b ctxOf`: every call in
  scope that meets its function's `Pre` ends in an observable meeting its `Post` (a revert is
  allowed only where the spec does not say the call succeeds). `Holds.of_stage` moves it along a
  refinement stage, so a spec proved of SolidCore holds of the bytecode.
- `Ghost.lean`: ghost erasure. For a core language with assignments, requires, branches, loops,
  ghost statements, asserts and assumes, erasing well-formed ghost code changes no real state and
  no outcome when the ghost code terminates (`sound`, `complete`), so a spec over real state
  proved of the program with ghosts holds of the erased program (`spec_of_erased_real`).
  Straight-line ghost code always terminates (`ghostTotal_of_straight`).
- `TrustedBase.lean`: each item of the "Trusted base" in solar-verify's README as a named
  hypothesis, never an axiom, and `spec_of_verdict`, which takes the verdict itself as one.
- `TrustedBase/Hypotheses.lean`: each of those hypotheses stated precisely (`Hyps`,
  `Hyps.toAssumptions`, `spec_of_verdict_hyps`), with a witness that it is satisfiable, where cheap one
  that it is not trivially true, and its discharge for code without the feature (table below).
  `TrustedBase/Instances.lean`: c4's and Counter's discharged. `TrustedBase/Axioms.lean`: their
  `#print axioms`.
- `Export/`: specs generated by `solar-verify --emit-lean-spec` from `scripts/refinement/spec`.
- `Solar/C4.lean`: the c4 spec proved of SolidCore (`holds_source`), of solar's bytecode for the
  deployed storage (`holds_bytecode`) and for any storage given the solar-tv stage
  (`holds_bytecode_at`), bound to the manifest (`certified`); the wrong spec fails on a concrete
  call (`wrong_fails`).
- `Axioms.lean`: `#print axioms` for the theorems above: `propext`, `Classical.choice` and
  `Quot.sound` only.

## Trusted base as hypotheses

| README item | Lean |
| --- | --- |
| 1. Parser, VC encoding and solvers | `Verdict`, the hypothesis of `spec_of_verdict` |
| 2. `@custom:assume`, `@custom:trusted`, interface ensures | `Assumptions.assumptionsHold` |
| 3. No `delegatecall` into the contract | `Assumptions.noDelegatecall` |
| 4. keccak256 injective, images in `[2^128, 2^256)` | `Assumptions.keccakSeparated`, per call: injectivity cannot hold of all inputs |
| 5. Assembly slots disjoint, assembly memory-safe | `Assumptions.asmSlotsDisjoint`, `Assumptions.asmMemorySafe` |
| 6. `Math.mulDiv` summarized as OpenZeppelin's | `Assumptions.mulDiv` |
| 7. View and pure calls answer as functions of what they read | `Assumptions.viewCalls` |
| Opaque spec functions return values of their type | `OpaqueInRange` |

Stated precisely in `TrustedBase/Hypotheses.lean`:

| Item | Statement | Satisfiable / not trivial | Discharged |
| --- | --- | --- | --- |
| 2. `@custom:assume` | `Core.AssumesHold s σ`: no assume cuts off an execution of the core program from `σ` | `assumesHold_assumeX` / `not_assumesHold_assumeX` | no assume: `assumesHold_of_noAssume` |
| 2. `@custom:trusted`, internal | `Core.MeetsContract s req ens` | `meetsContract_assign` / `not_meetsContract_assign` | no trusted function |
| 2. `@custom:trusted`, external | `TrustedHold`: `Holds` of the trusted functions' specs |  | `trustedHold_nil`, `trustedHold_of_holds` |
| 2. Interface ensures | `InterfaceEnsures ens tr` over a transcript's call exchanges |  | no call returns: `interfaceEnsures_of_default` |
| 3. No `delegatecall` into the contract | `NoForeignWrites` within a call; `Reach` from deployment across calls | `Reach.refl` | `noForeignWrites_of_default` |
| 4. keccak256 | `KeccakSeparated S` of the call's preimages | `keccakSeparated_mapping` (six real mapping slots, kernel-evaluated) / `not_keccakSeparated_univ` | nothing hashed: `keccakSeparated_empty` |
| 5. Assembly | `AsmFree u`, stronger: SolidCore rejects assembly | `asmFree_example` / `not_asmFree_example` | by `decide`: `asmFree_c4`, `asmFree_counter` |
| 6. `Math.mulDiv` | `MulDivSummary impl`: agrees with `ozMulDiv` (`ozMulDiv_spec`: floor of the exact quotient) | `mulDivSummary_oz` / `not_mulDivSummary_unchecked` | no `Math.mulDiv` |
| 7. View calls | `ViewDeterministic self tr`: same target and calldata, from worlds agreeing on balances, code and the caller's storage, answer alike whatever the gas | `viewDeterministic_twice` / `not_viewDeterministic` | `viewDeterministic_of_default` |

`Hyps.satisfiable`: the whole structure holds on every call of some instance. Open: a call's keccak256
preimages and its transcript are supplied with `Hyps`, not yet derived from SolidCore's run
(`transcriptWith` computes a transcript from an interaction tree, but `Source.run` folds its tree
without exposing it, and SolidCore hashes inside its interpreter); `MulDivSummary` is not yet
instantiated with SolidCore's internal-call semantics; the interface ensures are a predicate on the
request and response, not yet built from an exported interface spec.

c4 needs none of them: `Assumptions.none_on`, and its spec has no opaque functions.

## Checking the exports

`scripts/refinement/spec/check.sh` regenerates the exports with `solar-verify` and fails if they
differ, checks that the annotated source is the corpus source with comments, and that the
manifest's bytecode sha256 is the runtime bytecode's.

## Not done yet

- Loop invariants have syntax but no meaning yet; they wait on Loom's loop rules in
  `vendor/loom`. Ghost erasure is proved for the core language, not yet tied to SolidCore
  statements.
- A spec holds per call; invariants are not yet chained along a sequence of calls.
- `Env.ghostEquiv` is defined but the lemma that ghost-free terms ignore ghosts is not proved.
- `holds_bytecode_at` takes the solar-tv c4 stage as a hypothesis, because the pinned solar-tv
  c4 milestone proofs do not build here.
